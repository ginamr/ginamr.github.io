User Research Fall Quarter 2017

@UCI

User Interviews

Before beginning development, I interviewed five people from the field of Computer Science. It was important to understand potential users of my site to determine what content I should include and user expectations. The interviewees consisted of one peer and four full time employees of MobilityWare, a local gaming company.

View the user interviews

Competitor Analysis

Competitor analysis is the process I utilized to identify competitors and evaluate them to determine their strengths and weaknesses in order to better design my own website. I analyzed fellow software engineer portfolios, as well as other portfolio websites including LinkedIn, Instagram, and GitHub. I chose these direct and indirect competitors because they are all viewed by Software Engineer hiring managers and all involve resume and bio information.

View the competitor analysis

Feature Value Matrix

A feature value matrix maps features to numeric values which rank them in order of priority based on three parameters: user value, business value, and development effort. I selected the features that met given requirements and interviewee recommendations.

View the feature value matrix

Feature Prioritization

After ranking features via the feature value matrix, I plotted them on two plots, a simple line low to high priority and then a Kano Model coordinate plane which classifies features based on all parameters. I implemented the features with lowest technical effort and highest value first, then went on to implement those with higher technical effort and high value.

View the feature prioritization

User Stories

User stories are natural language descriptions of software requirements and define criteria for meeting end user goals/system requirements. I based my user stories on the prioritized features list. For my website, the user I chose is a hiring manager and the stories all involve defining success criteria for the intended end user experience. For example: I want to return to the top of the website after scrolling to the bottom, so that I will be able to visit the bio again. I know I’ve succeeded when I recognize the button and use it to navigate to the top of the screen.

View the user stories

Cognitive Walkthrough

A cognitive walkthrough is a usability evaluation method. I walked users through a series of tasks to perform on my website. I conducted 3 cognitive walkthroughs and discovered a lot of things I can improve in my website.

View the cognitive walkthrough

User Test

I conducted 2 user tests via UsabilityHub.

The first is a Click Test which allows a single click for the response and I ask two questions. I show a screenshot of my website on a secondary page and ask the user where they would click to go back to the main/home page and why they clicked there. I have 13 responses as of 11/28/2017.

View the first user test result

The second is a Question Test which sets the stage by telling the user to imagine they are a hiring manager at Microsoft looking at a prospective employee’s portfolio website. Then I show a screenshot of my home page and ask what the first thing they would look for would be. I have 13 responses as of 11/28/2017.

View the second user test result

Summary of Findings

User Interview Findings:

Based on feedback consistent across all interviewees, I decided to include only my GitHub and LinkedIn account links, since Facebook and other social media based links would have been irrelevant/informal.

From my interview with Joel Duggan, I decided to link to where the user can download an application I contributed to at Microsoft.

From my interview with Curtiss Murphy, I decided to have images with links as well as brief overviews for each of the projects and provide the ability for the user to delve in deeper if so desired.

From my interview with Jill Wilder, I decided to include personal pictures and projects that highlight my best work to date.

From my interview with Russ Carroll, I included a skills section to emphasize that I am capable of doing the job the user may be hiring for.

From my interview with Angel Azpitarte, I included my personal interests in my bio, but limited them to a sentence as to not distract from my technical abilities.

From the competitor analysis, I determined photo content and minimalistic design add value to a portfolio. I discovered efficiency is key and too many high-quality photos or loading screens detract from the experience. I also determined what would make my website more valuable than an existing social media sites is the ability to create unique deigns and richer content.

The feature value matrix and prioritization guided the implementation. The features I listed in order of priority: name, meta tags, external stylesheet, email, sections, navigation, bio image, personal bio, accessibility, contact block, HTML5 semantic markup, media queries, social media links, java script meaningful functionality, photos, and music. From the Kano Model I determined name, meta data, external stylesheet, and email were the lowest effort and highest value. In the end, I implemented all features except for a music section which I decided against since it felt distracting.

User stories led to my cognitive walkthrough. I had users attempt to fulfill the success criterion from the user stories. For example, I had users scroll to the bottom of my site and asked them how they would navigate to the top again. All participants easily found the “Back to Top” button and clicked it thereby fulfilling the success criteria from the corresponding user story.

For my first user test, I collected 13 responses as of November 28, 2017. 12/13 users clicked the correct location. The other user appears to be an obvious outlier and probable error since the click was not near a button, they waited 3 times longer to click, and they said, “To see what would happen”.

The second user test yielded expected results. Given they were a hiring manager, what if the first thing they would look for? Responses were text entry based and responses centered around experience, major, and qualifications. This aligns with what I expected from the user interviews.

Incorporation of Findings

The following changes are based on information I gathered during cognitive walkthroughs. I plan to change my contact information so that my email is both on the top of my main page as well as the bottom. Moreover, the email will be a simple envelope which automatically links to an email message. I also intend to put my photo to the right of my bio and make it slightly larger. I also will change the bio so that my major and minor are clearly labeled and listed. I also will add the number of years I have studied computer science.

From competitor analysis information, I intend to alter my navigation so that it scrolls to specific sections on my main page and with a drop-down menu including all four projects. My existing solution is a “Back to Top” button on the bottom of each page. I expect the user to scroll all the way through and subsequently return to the top. However, the cognitive walkthrough revealed this is not the ideal navigation and it is clear it can be improved.
